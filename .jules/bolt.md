
## 2025-02-17 - React Component Re-renders in `EditorPage.tsx`
**Learning:** `EditorPage.tsx` manages a massive amount of state for the entire editor shell (files, content, compilation state, AI chat messages, settings, UI visibility). Every time *any* of this state changes (e.g., typing a character in the editor, receiving an AI message, updating compile progress), the entire page re-renders. This passes down new object references (like the `leftPane`, `editorPane`, `composerPane`, and `previewPane` props) to the child components (`EditorShell`, `PdfViewer`, `LeftPane`, `ArtifactPane`, `ComposerPane`). Because these complex nested objects are created fresh on every render in `EditorPage.tsx`, child components lack memoization opportunities unless the props structure is flattened or the components themselves are heavily memoized.
**Action:** Memoize large components, specifically child components of `EditorPage.tsx` like `EditorShell`, `ArtifactPane`, `ComposerPane`, `PdfViewer` and `LeftPane` or flatten the props structure. In the context of "ONE small performance improvement", the best approach is to wrap the heaviest leaf components (like `MonacoEditor`, `PdfViewer`, `LeftPane`) or the layout components (`EditorShell`, `ArtifactPane`, `ComposerPane`) in `React.memo` to prevent cascading re-renders when orthogonal state (like typing in `MonacoEditor` causing a `content` update, which triggers a full tree render including `PdfViewer` and `LeftPane`) changes.
