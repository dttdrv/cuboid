## 2024-05-24 - [Path Traversal in API]
**Vulnerability:** API endpoints in `backend/src/server.ts` taking user input (`projectId`, `jobId`) were directly joined with paths using `join` in `backend/src/store/localStore.ts` without proper sanitization. This allowed attackers to escape the project directory context and overwrite or read arbitrary files by sending payload containing `../` sequences.
**Learning:** Even internal backend services handling project resources must securely sanitize all parameter values used for file operations to prevent path traversal outside expected boundaries.
**Prevention:** Always use safe path sanitization utilities, like the implemented `safeJoin` and `toSafeRelativePath` in `backend/src/utils/path.ts`, to securely construct file paths and ensure the final path remains within the intended boundaries.

## 2024-05-24 - [Command Option Injection in latexmk]
**Vulnerability:** In `backend/src/services/compileQueue.ts`, the user-provided `mainFile` is eventually passed to `latexmk` via the Rust compiler worker (`backend/rust/compile_worker`). By supplying a `mainFile` that begins with a hyphen (e.g., `-shell-escape`), an attacker could inject arbitrary options into the `latexmk` command invocation, circumventing intended security boundaries.
**Learning:** Always validate that user-provided values used as filenames do not resemble command-line options when they are passed as arguments to underlying external processes. Options injection is a severe risk in command builders that don't enforce positional argument separators (like `--`).
**Prevention:** Explicitly reject inputs intended as file names or paths that start with `-`. Alternatively, ensure the external command invocation uses `--` to demarcate the end of options before accepting arbitrary positional inputs.
