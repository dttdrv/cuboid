## 2024-05-24 - [Path Traversal in API]
**Vulnerability:** API endpoints in `backend/src/server.ts` taking user input (`projectId`, `jobId`) were directly joined with paths using `join` in `backend/src/store/localStore.ts` without proper sanitization. This allowed attackers to escape the project directory context and overwrite or read arbitrary files by sending payload containing `../` sequences.
**Learning:** Even internal backend services handling project resources must securely sanitize all parameter values used for file operations to prevent path traversal outside expected boundaries.
**Prevention:** Always use safe path sanitization utilities, like the implemented `safeJoin` and `toSafeRelativePath` in `backend/src/utils/path.ts`, to securely construct file paths and ensure the final path remains within the intended boundaries.

## 2024-05-24 - [Prototype Pollution via extraBody]
**Vulnerability:** The `mergeExtraBody` function in `backend/src/services/aiRouter.ts` merged user-controlled input (`extraBody`) into a `payload` object. While it correctly blocked required core fields like `model`, `messages`, and `stream`, it failed to block sensitive JavaScript internal keys like `__proto__`, `constructor`, and `prototype`. If a user sent an object with these keys, it could lead to prototype pollution, potentially allowing an attacker to manipulate object properties globally.
**Learning:** When merging arbitrary user-controlled JSON or objects into application state or request payloads, it is critical to explicitly block internal JavaScript properties (`__proto__`, `constructor`, `prototype`) to prevent prototype pollution vulnerabilities.
**Prevention:** Always include `__proto__`, `constructor`, and `prototype` in explicit blocked sets when merging or copying properties from user-provided objects, or use robust merging libraries that handle prototype pollution safely.
